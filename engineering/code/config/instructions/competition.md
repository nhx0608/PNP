# 执行须知

## 最重要的一条：Office 文件必须用 office 工具

`.docx` / `.xlsx` / `.pptx` / `.csv` 是压缩包或结构化格式，**不是文本**。引擎自带的 `read` / `write`
读不了也写不对它们：`read` 会返回 "Cannot read binary file"，而 `write` 会生成一个后缀是 .docx、
内容却是纯文本的**损坏文件**，看起来成功，实际上打不开。

- 读这四类文件，只能用 `office_docx_extract` / `office_xlsx_read` / `office_pptx_extract` / `office_csv_read`。
- 写这四类文件，只能用 `office_docx_create` / `office_docx_replace_paragraphs` / `office_xlsx_write` /
  `office_pptx_create` 等 `office_` 开头的工具。
- `read` 报 "Cannot read binary file" 时，**不要重试，也不要改用 `write` 绕过**——直接换成上面对应的
  `office_` 工具。记不清工具名就调 `server_info` 列出全部工具。
- 只有 `.md` / `.txt` / `.json` / 代码这类纯文本，才用引擎自带的 `read` / `write`。

## 先看数据，再下结论

分析、统计、总结类任务，**必须先用 `office_csv_read` / `office_xlsx_read` / `office_data_aggregate`
真正读到数据，再写结论**。没读过就写出来的数字是编的，即使文件生成了也算失败。需要分组、求和、
均值、排序、筛选时用 `office_data_aggregate`，它算得比心算准。

## 产物优先：先落盘，再打磨

**没有产出文件，等于这道题零分**——哪怕分析做得再好。所以顺序永远是：读到数据 → **先把文件写出来** →
有余力再改进它。不要把预算耗在反复读取和验证上，导致最后什么都没写。

- **同一个工具、同样的参数不要重复调用第二次。** 结果不如预期时，是参数要改，不是再试一遍。
  仔细看返回里的提示：工具会说明它实际做了什么、以及该调整哪个参数（例如没分组时会提示用 `groupBy`）。
- 某个工具连续两次都没给出你要的结果，就用手头已有的数据先完成文件，并在最终回复里说明哪部分不完整。
- 时间紧张时，宁可交一份内容简略但结构完整、路径正确的文件，也不要交空手。

## 路径与产物

- 请求中给出的路径可能是绝对路径，也可能在当前工作目录之外。一律按原样使用，不要改写、不要移动到工作目录里。
- 产物必须写到请求指定的位置和文件名；目标目录不存在时先创建。
- 未被要求修改的已有文件不得改动、覆盖或删除；需要中间文件时另起新文件名。
- 请求没有指定输出位置时，写到当前工作目录，并在结论里给出绝对路径。

## 运行环境

- 系统是 Windows，命令行是 PowerShell；不要假设存在 Git Bash、bash、python 或 curl 等工具。
- 路径分隔符用 `\`，含空格的路径要加引号。
- 优先使用已提供的 `office` 工具处理 docx / xlsx / pptx / csv 的读取、生成与修改；这些工具比脚本更可靠。
- 打开 Notepad、经典 Outlook 或新 Outlook 前先调用 `desktop_list_apps`，再按返回的 appId 调用 `desktop_open_app`。工具只报告启动/激活事实；未核验界面、登录或业务操作时不得声称完成这些步骤。
- 只有 `office` 工具做不到的事（文件搬移、目录整理、调用本机应用等）才用 PowerShell 命令完成。
- 不要为了完成任务去联网安装第三方库。

## 结果核验

- 声称完成之前，必须核验产物。对 `.docx` / `.xlsx` / `.pptx` 用 `office_doc_verify`：它会检查文件
  是否真实存在、是不是有效的 Office 文档（而不是被写成文本的损坏文件）、以及必须出现的关键词、
  页数、sheet 数、汉字数是否达标。纯文本产物重新读一遍确认内容。
- `office_doc_verify` 报告不通过时，按它指出的问题修一次。**最多修两轮**：两轮之后仍不达标，
  就保留当前文件，并在最终回复里如实说明哪一项没达到。核验是为了发现问题，不是无限返工的理由——
  文件已经写出来的前提下，如实说明缺陷远好于为了追求完美而超时。
- 工具报错或结果缺失时如实说明并换一种方式重试，不得凭猜测宣布成功。
- 不要伪造文件内容、执行结果或统计数字。一个后缀正确但内容是路径或占位文本的文件，等同于没有完成。
