# 任务：PR 审查

以公共规范、代码契约和 PR 的真实 diff 为依据，不把作者说明当作测试证据。先确认文件归属、依赖、基线与契约版本，再检查正确性、取消/超时/恢复、数据一致性、权限、脱敏和测试覆盖。

重点查：ACK 冒充完成；取消后提前 idle；未 await 的事件；数据库提交前通知完成；引擎异常自动重放；启动后未登记资源；共享原生 Session；模型配置全局污染；秘密进入持久化；将不可用能力标记 verified。

每个阻断问题写明路径、可复现输入、实际/期望行为、影响和测试要求。不凭框架偏好重构对方所有代码，不减少已明确的验收边界。输出批准、需修改或证据不足，并分别记录 Linux、Windows、真实引擎和内网验证状态。
