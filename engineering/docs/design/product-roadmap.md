# 产品评审与实施路线图：工作台、配置中心、办公扩展、消息能力

> 生成于 2026-09-09。设计记录，不是已实现状态；实现进度见文末。
> 评审范围超出赛题本身：从使用者角度看这套系统缺什么。

## 1. 评审结论

Against the competition the delivery is protocol-complete and honestly evidenced: two real engines over two different protocols, pinned by tarball hash, every mandated 6217 capability plus the question/permission loop, an offline bundle that starts on a Windows box with no Node/Git/network, and a gate that is green on the exact working tree (483 unit/adapter tests, 481 pass, 2 skipped; typecheck and boundaries PASS; real-engine e2e 20/21 on both engines). The 70% is leaking on task completion, not protocol, and the leaks are cheap to close: a textual confirmation request (office_103) and a hallucinated tool name written as prose (office_011) both end as "successful" 204 runs with no artefact; office_018 needs a column-vs-column comparison the aggregate tool cannot do; zh-CN Excel CSVs are GBK; and a harness that passes any non-loopback --host kills the process before it listens. The one number everyone is steering by - Pi 0/7 mechanical - was measured on 2026-09-08, BEFORE today's uncommitted Pi payload fix that took its live check from 6/8 to 8/8, so the second engine's real contribution is currently unknown and must be re-measured before any tool-count or priority decision is trusted. Three other things the orchestrator's snapshot no longer reflects: GET /session/:id/event (with the schema-v2 index) is already implemented, the first text checkpoint floor is already 256 bytes so short answers do stream, and server.gap/compaction advertising/redaction fixes are in the tree. All of it, plus src/tools/desktop-mcp/ itself, is uncommitted - a clean checkout ships a settings.json pointing at a desktop MCP that does not exist.

As a product it is a gateway you operate from two PowerShell windows and a raw SSE dump: nothing shows which sessions are running, what tool an engine is inside, which native events it emitted, or why a case failed; the two-layer common+cores configuration is real and validated but has no read/validate/write surface, skills are projectable by OpenCode yet unreachable from settings, and there is no messaging capability at all. The four design tracks are sound and all dependency-free; this roadmap merges them onto one static route (assets/ui served by Fastify from the already-packaged assets/ directory, no build step), one rich session-list route, the existing per-session event route, one export route for the cross-engine compare page, and one /config family, and it rejects the transient delta stream, the filtered SSE, the copy-ui build step and the raw-text config body as unnecessary or risky. The honest trade-off: none of the console work completes a single evaluation case, so the roadmap puts the cheap 70% fixes (commit + re-measure, instruction hardening, --host, data_aggregate, doc_verify) first and interleaves the console minimum-viable demo right after them because it is the only way the 20%+5% reviewers ever see the multi-engine thesis the code already proves. Every package names what it can regress; the build is green today and staying green is the main constraint.

## 2. 最大的失分点

### 1. The second engine's objective contribution is unknown on the current tree, and the current tree is uncommitted

**为什么**：The only per-case real-model run (2026-09-08) shows Pi 0/7 with every case ending after one `ls`; today's uncommitted Pi before_provider_request fix addressed exactly the symptom that made GLM-4-Flash answer 'no task received' (live check 6/8 -> 8/8). Best-of-engines scoring means Pi is worth its marginal coverage only, and nobody knows what that is now. Separately, src/tools/desktop-mcp/, aggregate.ts, doctor-config.mjs, ARCHITECTURE.md and today's Core/driver fixes are untracked or unstaged: a clean checkout or a git-based package ships a settings.json that names dist/tools/desktop-mcp/main.js and a Pi that still mis-serialises prompts.

**怎么修**：R-00: commit the working tree (schema v2 as its own change per AGENTS.md), fix the office_002 expectation, add a package-release self-check that every dist/tools/*/main.js named by settings.json exists in the staged bundle, then re-run docs/run-eval-tasks.ps1 on both engines and record the per-case table in verification/results.json. Every later priority decision reads that table.

### 2. Runs that end without an artefact are accepted as successful

**为什么**：office_103 finished with '请确认是否执行删除操作' (204, finish=stop, nothing deleted) and office_011 finished with the literal text 'office_docx_open {...}' (no such tool, no output file). Both are normal finish=stop turns to the gateway; the auto question policy never fires because the engine asked in prose. The instruction file says 禁止请求确认 but names no concrete alternative and nothing checks the artefact by code before the model claims completion.

**怎么修**：R-01 adds two instruction lines (deletion: dryRun then execute, never ask; never write a tool call as text, call server_info when a tool seems missing). R-07 adds doc_verify/doc_diff so the model checks existence, OOXML integrity, CJK count (the grader's own [㐀-鿿] rule), required text, headings and preserved numbers before finishing, and every write tool's summary line tells it to.

### 3. office_018 needs a row-wise comparison and hidden CSVs will be GBK

**为什么**：data_aggregate compares a column against a constant only; '当前库存 低于 安全库存' has to be done in the model's head, which is where small models fail a difficulty-4 case. csv_read is UTF-8 only; a CSV saved by zh-CN Excel decodes to mojibake headers and every column lookup fails with NO_MATCH.

**怎么修**：R-06: filters[].otherColumn, derive[] (缺口 = 安全库存 - 当前库存, pct), output:'rows' with columnsOut and sort, plus decodeText with BOM/UTF-16/strict-UTF-8/GBK fallback via Node's bundled ICU TextDecoder. Zero dependencies, ~150 lines.

### 4. Any non-loopback --host aborts startup

**为什么**：The spec lists --host as 必须支持 with default localhost; main.ts throws UNSUPPORTED_BIND_ADDRESS for anything but 127.0.0.1/localhost/::1. A harness that runs the client in another container and starts the gateway with --host 0.0.0.0 loses every case for that engine before the first request; scripted harnesses do not read INSTRUCTION.md.

**怎么修**：R-02: accept the value, print a loud gateway.bind.non-loopback warning (the gateway has no authentication), keep localhost as the default, offer PNP_BIND_LOOPBACK_ONLY=1 to restore the refusal. The owner can veto this one; it is a security-posture change.

### 5. Excellent engineering that nobody can see

**为什么**：There is no HTML anywhere in the gateway. Engine-native passthrough (engine.extension with acp/pi namespaces), the compaction signal, session fencing, the two-layer configuration, per-session event history and the Job Object process host are discoverable only by reading TypeScript. INSTRUCTION.md never mentions solution/docs/ARCHITECTURE.md although the packager copies it precisely for the 20%; code/README.md still says it is not shipped.

**怎么修**：R-01 signposts the design record now. R-03/R-04/R-05 ship a dependency-free console at /ui/ (sessions, live timeline with verbatim native events, conversation, interactions, artefacts) and a two-engine compare page over exported runs, served by Fastify from assets/ui with no build step.

### 6. Configuration has the right model and no surface; skills are built but unreachable

**为什么**：common + cores.<engineId> with additive merge is exactly what the owner asked for and it already reaches both engines natively, but nothing reads the effective configuration, validates a candidate or applies one, and the schema has no skills key although AssetBinding kind 'skill' and OpenCode's skills/<id>/SKILL.md projection exist. Per-engine native options live in three unrelated places.

**怎么修**：R-09 (read + validate + provenance routes on the existing parser), R-10 (write with optimistic concurrency, contained file editing, config page), R-13 (skills map merged by id, projected natively by OpenCode and by Pi via --skill and verified through get_commands), R-18 (engine describe() and an opaque cores.<id>.native block), R-19 (reload for new sessions).

### 7. No messaging capability and no safety boundary for the owner's planned CLI senders

**为什么**：office_028 scores honesty credit only; the owner's next step is CLI tools that send mail/IM, which is an irreversible external side effect. Pi classifies permissions by server-level sideEffect and OpenCode never asks for MCP tool calls, so a send tool dropped into the office server would send under a write:allow policy on both engines; DELETE /session cascades every gateway table so no proof of a send would survive a judge's cleanup.

**怎么修**：R-11: a third stdio MCP server (messaging) with channels declared in config, recipient allow-list and live switch carried only through environment variable names, preview/send two-phase protocol with a content-bound single-use token, content-derived dedup key with O_EXCL markers, append-only redacted ledger under runtime/, closed outcome vocabulary and no retry; dry-run by default. R-12 makes the Pi bridge honour per-tool _meta so the permission operation is messaging_send, not the shared 'external' class.

### 8. office_002 can never carry the evidence the judge asks for

**为什么**：The manual criterion is 'Outlook 窗口出现'; desktop_open_app returns activation_requested and nothing can observe a window, so the trace can only say the launch command returned.

**怎么修**：R-08: desktop_list_windows (Get-Process MainWindowTitle), waitForWindowMs polling on desktop_open_app returning windowObserved, and desktop_screenshot as human evidence; all PowerShell 5.1 built-ins.

## 5. 明确拒绝的设计

- **Transient, unsequenced message.text.delta SSE broadcast (visual-console VC-3)**
  - 拒绝理由：Superseded: the working tree already lowers the first-checkpoint floor from 4096 to 256 bytes with the amortised quarter-growth rule intact, so a 1-3 KB answer now produces several persisted checkpoints at up to ten per second. Adding a second, non-replayable event type plus a Core change in the text.delta path buys sub-second smoothness at the cost of a new SSE vocabulary entry and regression risk in the most sensitive code. Revisit only if the Edge walkthrough shows the checkpoint cadence is visibly insufficient.
- **GET /event?session= filtered live stream and filtered Last-Event-ID replay (VC-2 part)**
  - 拒绝理由：GET /session/:id/event with the events_by_session index is already implemented and paged; the executor has one slot, so the global stream is small enough to filter client-side. A second replay path would duplicate the gap-reporting logic that was just hardened.
- **Schema v2 index migration as a new package (VC-2b)**
  - 拒绝理由：Already in the working tree (PRAGMA user_version 2, CREATE INDEX events_by_session). It only needs to be committed as its own change per AGENTS.md (done in R-00).
- **Framework build for the UI (Vite/esbuild with React/Svelte), a ui/ source directory copied into dist/ui by a copy-ui.mjs step, or 'ui' added to KEEP_DIRS (VC-1 alternative, CC-5)**
  - 拒绝理由：Any build step or devDependency is a second toolchain to pin, reproduce and stamp, and a CDN temptation that the offline judge box would silently break. assets/ is already in package-release KEEP_DIRS and shipped verbatim, and Fastify can serve an allow-listed file map itself; hand-written ES modules are enough for six pages.
- **Raw text-body PUT /config/files with a per-route parser flag (CC-2)**
  - 拒绝理由：The gateway deliberately replaced every content-type parser with a JSON catch-all because PowerShell and curl send bodies without a header; fighting that for one route risks the tolerance that protects evaluation cases. A JSON body { text, ifMatch } is equivalent and needs nothing.
- **POST /console/open-path launching explorer.exe on a path from the page**
  - 拒绝理由：Turns the unauthenticated loopback console into a local command launcher (AGENTS.md rule 8 spirit). Copy-to-clipboard plus a stat-only existence check is the honest maximum.
- **Bearer token or any minted credential for the /config API**
  - 拒绝理由：It would be the first credential the gateway mints and would have to be shown somewhere (the page). Same-origin loopback is not an auth boundary either way; PNP_CONFIG_READONLY=1 is the lever a locked-down deployment actually needs.
- **Persisting configuration in SQLite with settings.json as a seed**
  - 拒绝理由：Creates a second truth that pnp.cmd config, doctor, PNP_SETTINGS relocation and the packaged file cannot see, and needs a SQL version bump with dual review for a presentation problem.
- **A write endpoint that accepts credential VALUES (POST /config/environment writing local.env)**
  - 拒绝理由：The gateway binds loopback with no caller identity; a value-accepting route makes every local process a credential writer and puts a secret on a wire the Redactor never sees. Names on the page, values via pnp.cmd config or local.env, restart to apply.
- **Hot-patching resident engine channels on reload (rewriting opencode.json or restarting the Pi process in place)**
  - 拒绝理由：Drops engine-side history and has the gateway driving engine internals, against the owner's perceive-do-not-drive rule. The 409 ENGINE_BINDINGS_CHANGED fence is the honest signal.
- **Folding skill text into Pi's --append-system-prompt instead of native skill projection**
  - 拒绝理由：Flattens Pi's progressive disclosure into rules, can blow the system prompt at 1 MiB per asset, and makes 'skills' indistinguishable from 'rules' on one engine. --skill <dir> and get_commands are documented in the pinned 0.85.1 package.
- **A CommandToolBinding with transport 'cli' or an engine-native extension as the home for messaging senders**
  - 拒绝理由：settings.ts accepts only stdio/streamable-http and both drivers drop cli/native bindings today, so a cli binding would silently vanish; a native extension would be written twice with divergent approval semantics. A stdio MCP server reaches both engines from one settings entry, as desktop just proved.
- **Putting send tools inside the office MCP server, or using the server-level 'external' class as the messaging permission operation**
  - 拒绝理由：Pi classifies by server-level sideEffect, so mail_send in the write server would pass under write:allow; a shared 'external' operation lets one 'always' approval of desktop_open_app cover every later send in the session.
- **An InteractionBroker rule refusing remember=true for certain operations**
  - 拒绝理由：Puts tool knowledge into Core, which must not know a specific tool; the content-bound single-use send token already limits an always-approval to previewed content.
- **Session and engine id injected into every stdio MCP server's env by both drivers (messaging P8)**
  - 拒绝理由：Touches both drivers and the ACP binding fingerprint for a ledger nicety; ship only if the audit view later needs it.
- **pdf_extract via pdfjs-dist**
  - 拒绝理由：A new runtime dependency that must be vendored, hashed and dual-reviewed as its own change; credible Chinese PDF text needs ToUnicode CMaps, so no hand-rolled substitute is honest. Deferred, not dismissed - a separate dependency-freeze change if the owner wants it.
- **Office COM automation (Word ExportAsFixedFormat, Excel recalculation, PowerPoint thumbnails) and a web_search tool**
  - 拒绝理由：COM needs an installed, signed-in Office in an interactive session and leaves orphan processes on failure; a public search endpoint is useless offline and fragile online. If ever added: a separate server, enabled:false, or a configurable urlEnvironment for an intranet search.
- **Separate text_stats / docx_diff / pptx_diff / office_package_check tools**
  - 拒绝理由：Four calls and four chances for the model to skip one; folded into doc_verify (spec-driven, evaluates expectations mirroring eval-expectations.json) and doc_diff, with the logic in modules.
- **A 'friendly' normalised timeline that folds engine.extension into generic thinking/tool/done rows, or marks a run done on the last text frame**
  - 拒绝理由：Reads better for ten seconds and lies about both engines and about completion (AGENTS.md rules 2 and 3). Native rows stay verbatim under their namespace; completion renders only from session.idle/session.error/step-finish.
- **A multi-engine hub gateway or a server-side proxy fetching another gateway's export for the compare page**
  - 拒绝理由：Makes the gateway a client of another gateway - a new trust and lifecycle surface for a presentation problem. A GET-only, loopback-only CORS allowance on the export route plus file import covers it.
- **Gateway-side interception forcing a permission prompt for fs_move/fs_copy on OpenCode**
  - 拒绝理由：OpenCode never asks for MCP tools natively; forcing a prompt from the gateway is driving the engine. Tool-level guards (dryRun, protected locations, no overwrite) hold regardless of which engine asks.

## 7. 不能破坏的性质

- The 16 mandated routes and their shapes: POST /session, GET/DELETE /session/:id, GET /session/status ({id:{type}}), blocking POST prompt_async returning 204, GET /session/:id/message (user/assistant/tool with info.finish and step-finish), abort/stop, GET /event with 15 s heartbeat, retry and Last-Event-ID replay, question/permission list and reply, health, diagnostics; the {code,message} error envelope; every new route is additive and namespaced (/ui, /config, /session/:id/{run,export,artifacts/check}, GET /session).
- Completion semantics owned by Core: session.idle and 204 only after finishRun commits; step-finish only when state=completed and finish=stop; a request ACK is not completion and a cancel ACK is not stop evidence; unproven stops fence the session with EXECUTION_UNCERTAIN; the console must render exactly this.
- AGENT_ENGINE is authoritative, --engine may equal it, disagreement fails with ENGINE_CONFIGURATION_CONFLICT, neither fails with ENGINE_NOT_FOUND; mock is refused outside PNP_MODE=development; no automatic fallback to another engine or model.
- scripts/check-boundaries.mjs stays PASS: adapters (src/engines, src/drivers, src/integration) never import Fastify, node:sqlite, GatewayCore, src/storage, src/gateway, node:child_process or src/config; Core and Gateway never import an engine or protocol SDK; Core never branches on an engine name; adapters take configuration only from IntegrationContext.

- Offline delivery constraints: solution/{INSTRUCTION.md, code/} built by package-release.mjs; no build step, no CDN, no network at runtime on the judge box; assets/ui served verbatim from KEEP_DIRS; zero new runtime dependencies; engines.lock.json hashes and package-lock unchanged; package-release selfCheck and the credential/internal-prefix scans pass.
