# DFX、验证与发布门禁

## 1. 可靠性目标

PNP 是单机系统，不承诺多机容灾或节点失效时无中断继续执行。可靠性目标是：状态不因普通进程重启丢失；Harness 故障不拖垮网关；任何不确定执行不被伪装为成功；未核验清理不允许下一轮与旧执行重叠。

| 故障 | 必须行为 |
|---|---|
| 模型配置缺失/组织拒绝 | 执行前明确失败，不换模型或绕过权限 |
| 引擎启动失败 | 处理已登记资源；不产生无法追踪的原生实例 |
| open 超时后返回 Channel | 处理迟到资源；停止证据不足时保留阻断 |
| 工具未结束而引擎报完成 | 协议错误；不生成正常 stop |
| 取消 ACK 但工具继续执行 | 继续取消/终止；不提前 idle |
| 工具结果丢失 | 记录 gateway-observation；不伪造 tool result |
| SQLite 写失败 | 不发布成功；阻断新 Run，保存可用诊断 |
| SSE 客户端慢或断开 | 关闭慢连接；不重执行任务；消息快照仍为事实源 |
| 网关崩溃 | 持久化 Run 记 interrupted，核验所属 Host/Job 后恢复准入 |
| 外部提交结果未知 | 不重试原 Prompt 或外部操作 |
| Session 删除失败 | 保留 deleting 状态；不删除用户产物 |

## 2. 可用性和恢复

`/health/live` 表示网关进程存活，`/health/ready` 表示共享执行控制允许接新任务，不代表所有模型与工具已经实际验证。Engine/Model/CLI 的能力测试由 Doctor 和正式验收给出，不能通过检查环境变量存在来宣称全部可用。

Job Object 和资源归属核验只覆盖本系统受管执行进程。持久化恢复不会自动执行业务任务，也不声称外部副作用回滚。

## 3. 性能与资源

默认并发 Run 数为 1，避免同桌面干扰。SQLite Worker 队列有上限；JSONL 帧最大 4 MiB，规范事件最大 1 MiB，累计文本最大 8 MiB；大型产物使用引用。文本输出按 100ms/4KiB 级别合并检查点，最终结果完整写入。

SSE 有限缓冲，写入背压不能无限消耗内存。长连接不阻塞取消和健康检查。工具、启动、交互、运行及收尾均有配置化时间边界。资源阈值是实现约束，不是已经测得的吞吐或 SLA。

## 4. 安全

网关默认仅监听 loopback，非本地访问不作为此交付的认证场景。凭据只来自授权环境或临时绑定，不能进入 SQLite、错误响应、产物或源码。日志脱敏不是对恶意编码泄漏的充分安全隔离；高风险内网访问仍依赖授权服务和操作系统边界。

原生 Harness 的默认遥测、自动更新、外部网络和全局资产加载必须由引擎工作包核验。Shell 不是权限隔离机制；`shell:false` 只避免额外命令解释层，不限制模型自己调用的原生工具。

## 5. 测试层级

| 层 | 执行位置 | 证明内容 |
|---|---|---|
| 公共单测 | 开发环境 | 状态、存储、顺序、取消、交互、资源登记 |
| 公共 HTTP 契约 | 安装依赖的开发环境 | Fastify 真实路由、阻塞 204、错误、SSE |
| A/B 协议夹具 | A/B 各自环境 | ACK/终态、分片、取消、断流、事件映射 |
| 引擎真实冒烟 | Windows 开发环境 | 安装、原生进程、Session、模型绑定、资产 |
| 内网联合验收 | 内网 Windows | 真实模型、工具、权限、业务材料和最终结果 |

## 6. 必测条目

- F01：title 可选、directory 必填、model 必填、未知资源与路径返回规范错误。
- F02：prompt_async 不在 ACK 时结束；最终消息持久化后才允许 204/idle。
- F03：同会话及全局执行槽串行；第二个并行 Prompt 明确 409。
- F04：会话、消息、channel/native 绑定在干净重启后可查询并原生继续。
- F05：取消、超时、引擎失败不伪造 stop；工具无结果以观察状态收尾。
- F06：启动超时、迟到 Channel、取消失效、不可证明停止都保持阻断。
- F07：Question/Permission 正常答复、重复答复、组织拒绝、取消及过期。
- F08：删除网关历史与原生目录，保留用户目录和输出文件。
- F09：实例锁、SQLite 事务、存储异常、重启中断记录及恢复检查。
- F10：中文/空格路径、UTF-8 分片、CRLF、U+2028/U+2029、过大/截断 JSONL。
- F11：stdout 协议与 stderr 诊断隔离、环境变量最小继承、秘密跨分片脱敏。
- F12：真实 Windows helper 建 Job、暂停入 Job、正常停止、网关被杀后的树清理。
- F13：SSE 心跳、慢客户端、断线、关机时连接关闭和消息快照兜底。
- E01：两种以上真实引擎使用同一 API，至少两种不同的南向接入实现通过共同契约。
- E02：每个正式引擎证明模型/工具/资产配置有效；恢复和取消能力按通道验证。
- I01：内模工具调用完整往返，拒绝错误参数，不使用幻觉字段继续执行。
- I02：员工助手权限、登录与调用回执；未知提交结果不盲目重试。
- I03：官方已有材料上的真实任务、文件可打开、数据可对账、GUI任务结果不被清理撤销。

## 7. 基线准入

`npm run foundation:check` 必须通过依赖锁、目标 Node、类型检查、公共单测、HTTP 契约和边界检查。共同基线的 SHA、契约版本与锁哈希写入交接记录。源代码存在不等于已经通过该门禁。

Windows Job helper 的实机验证与完整依赖构建是单独证据项。未验证时必须如实记录，不能通过删除测试或加入 always-pass 分支获得准入。

## 8. 发布准入

`npm run release:check` 检查：共同基线通过、真实 Pack 已实现、至少两种引擎的版本锁和内网验收证据、源码 commit 一致、Windows 身份和清理测试通过、无真实凭据、INSTRUCTION 可自动执行。

最终证据中禁止用 Mock、占位文件、仅声明 capability=true 或旧 commit 的结果代替真实验收。测试模型、回执和材料缺失时标记 not_run，不把它算作通过。
