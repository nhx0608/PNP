# DFX、验证与发布门禁

## 1. 可靠性目标

PNP 是单机系统，不承诺多机容灾或节点失效时无中断继续执行。可靠性目标是：状态不因普通进程重启丢失；Harness 故障不拖垮网关；任何不确定执行不被伪装为成功；未核验清理不允许下一轮与旧执行重叠；一个会话的不确定不影响其他会话。

| 故障 | 必须行为 |
|---|---|
| 模型配置缺失/组织拒绝 | 执行前明确失败，不换模型或绕过权限 |
| 引擎启动失败 | 处理已登记资源；不产生无法追踪的原生实例 |
| open 超时后返回 Channel | 处理迟到资源；终止自证静默即解除围栏，否则只阻断该会话 |
| 工具未结束而引擎报完成 | 协议错误；不生成正常 stop |
| 取消 ACK 但工具继续执行 | 继续取消/终止；不提前 idle |
| 取消或终止后停止不可证明 | 仅该会话 blocked 并从常驻表摘除；进程就绪不变；诊断列出原因 |
| 通道被终止后再次执行 | 按原生恢复能力恢复或新建原生会话；发布 `context.lost`；不拒绝执行 |
| 工具结果丢失 | 记录 gateway-observation 或终态 tool.observed 的 result_unknown 事实；不伪造 tool result |
| 输出或单个事件超限 | 截断并标记，`finish=length`；不失败、不断连 |
| SQLite 写失败 | 不发布成功；阻断新 Run，保存可用诊断；worker 重建后恢复就绪 |
| SSE 客户端慢或断开 | 只销毁该慢连接；不重执行任务；消息快照仍为事实源 |
| 网关崩溃 | 持久化 Run 记 interrupted；下次启动监听端口后异步核验归属记录；自证静默的解除围栏并删记录，其余只阻断对应会话 |
| 归属记录损坏或无法判定 | 不拒绝启动；记录移入隔离目录并计数；对应会话保持 blocked 直至删除 |
| 数据目录被另一个活着的进程拥有；存储打不开 | 拒绝启动，退出码非零，输出 `{code,message}` |
| 外部提交结果未知 | 不重试原 Prompt 或外部操作 |
| Session 删除失败 | 保留 deleting 状态；不删除用户产物 |

## 2. 可用性和恢复

`/health/live` 表示网关进程存活，`/health/ready` 表示共享执行控制允许接新任务，不代表所有模型与工具已经实际验证。`/health/ready` 只在存储不可用或关机排空时为 503；历史中断、阻断会话、归属核验进行中都不影响就绪。Engine/Model/CLI 的能力测试由 Doctor 和正式验收给出，不能通过检查环境变量存在来宣称全部可用。

Job Object 和资源归属核验只覆盖本系统受管执行进程。持久化恢复不会自动执行业务任务，也不声称外部副作用回滚。`/diagnostics` 读取失败只影响当次响应，不改变就绪。

## 3. 性能与资源

全局同时只有一个活跃 Run，避免同桌面干扰；跨会话请求有界排队，队列上限默认 8，可配；同会话第二个请求 409。常驻通道上限默认 16，可配，满额淘汰最旧空闲通道。SQLite Worker 队列有上限；JSONL 帧最大 4 MiB，规范事件最大 1 MiB，累计文本最大 8 MiB；超限截断并标记 `truncated`、`finish=length`，不断连、不失败；大型产物使用引用。文本输出按 100ms/4KiB 级别合并检查点，最终结果完整写入。

SSE 有限缓冲（2 MiB）；`text.delta` 只发增量，完整文本只在终态发布一次；单帧上限与缓冲上限对齐。写入背压不能无限消耗内存。长连接不阻塞取消和健康检查。工具、启动、交互、运行及收尾均有配置化时间边界，取消宽限期默认 15 秒。资源阈值是实现约束，不是已经测得的吞吐或 SLA。

## 4. 安全

网关默认仅监听 loopback，非本地访问不作为此交付的认证场景。凭据只来自授权环境或临时绑定，不能进入 SQLite、错误响应、产物或源码。日志脱敏不是对恶意编码泄漏的充分安全隔离；高风险内网访问仍依赖授权服务和操作系统边界。

原生 Harness 的默认遥测、自动更新、外部网络和全局资产加载必须由引擎工作包核验。Shell 不是权限隔离机制；`shell:false` 只避免额外命令解释层，不限制模型自己调用的原生工具。

## 5. 测试层级

| 层 | 执行位置 | 证明内容 |
|---|---|---|
| 公共单测 | 开发环境 | 状态、存储、顺序、取消、交互、资源登记 |
| 公共 HTTP 契约 | 安装依赖的开发环境 | Fastify 真实路由、阻塞 204、错误、SSE |
| A/B 协议夹具 | A/B 各自环境 | ACK/终态、分片、取消、断流、事件映射 |
| 引擎真实冒烟 | Windows 开发环境 | 安装、原生进程、Session、模型绑定、资产、能力包投影 |
| 内网联合验收 | 内网 Windows | 真实模型、工具、权限、业务材料和最终结果 |

## 6. 必测条目

- F01：title 可选、directory 必填、model 必填、未知资源与路径返回规范错误；请求体超限 413、媒体类型错误 415。
- F02：prompt_async 不在 ACK 时结束；最终消息持久化后才允许 204/idle。
- F03：全局一个活跃 Run。同会话第二个 Prompt 立即 409 `SESSION_BUSY`；跨会话第二个 Prompt 进入队列，在前一个终态后执行并返回 204；队列满 409 `GATEWAY_BUSY`；排队请求被 abort 时不产生 Run。
- F04：会话、消息、channel/native 绑定在干净重启后可查询；`ready` 会话原生继续；`needs-native-resume` 会话按契约第 5.2 节恢复或新建，轨迹含 `context.lost` 与观察态消息，不返回错误。
- F05：取消、超时、引擎失败不伪造 stop；工具无结果以观察状态收尾；`finalText` 为空时保留流式文本。
- F06：启动超时、迟到 Channel、取消失效、不可证明停止都只阻断该会话：该会话 409，新会话 204，`/health/ready` 保持 200；迟到 Channel 终止自证后围栏解除。
- F07：Question/Permission 正常答复、重复答复、组织拒绝、取消及过期；`source` 与 `reasonCode` 如实区分策略、用户、超时与取消；列表接口返回网关标识。
- F08：删除网关历史、原生目录与归属记录，保留用户目录和输出文件；blocked 会话可删除，删除后其归属记录消失。
- F09：实例锁、SQLite 事务、存储异常、重启中断记录及恢复检查；存储 worker 故障后重建，就绪随之恢复；`/diagnostics` 读失败只影响当次响应。
- F10：UTF-8 分片、CRLF、U+2028/U+2029、过大/截断 JSONL。
- F11：stdout 协议与 stderr 诊断隔离、环境变量最小继承、秘密跨分片脱敏。
- F12：真实 Windows helper 建 Job、暂停入 Job、正常停止、网关被杀后的树清理。
- F13：关机时取消进行中 Run、关闭 SSE 与数据库、无条件释放实例锁；SSE 断开后消息快照仍完整。
- F14：事件流背压与心跳。快客户端连续接收 1 MiB 单帧、200 个 64 KiB 帧与 5 个 1 MiB 帧（约 19 MB）不断流，`sequence` 严格单调；从不读取的慢客户端在缓冲上限 2 MiB 后被单独销毁，同时在线的快客户端不受影响；每帧停顿 20 ms 的客户端在 2 MiB 回答上完整收到 `session.idle`；`text.delta` 只携带增量，完整文本只在终态发布一次；心跳周期 15 秒，空闲 60 秒内至少 3 次，背压期间可丢弃且不占序号；`server.connected` 带 `retry:` 行。按序号补发不属于一期门禁。
- F15：中文与空格路径端到端。工作目录、原生数据目录、资产路径与工具参数含中文和空格（如 `D:\测试 数据\季度 报告.docx`）时，创建会话、投影资产、启动引擎、工具调用与轨迹落库全部正确；Windows 上 helper 命令行、JSONL 与 base64 往返不丢字符；轨迹中的路径与文件系统一致；`data/native/<engine>/<channel>/<session>/` 与 `hosts/*.json` 可读回。
- F16：真实归属核验路径（Windows 实机，不用桩）。六类记录：干净目录、`quiescent` 为真、辅助进程号已死、50 条历史记录、辅助进程存活、JSON 损坏或字段残缺。前四类启动后立即就绪且记录被删除；存活记录只阻断对应会话，其他会话 204；损坏记录移入 `hosts/quarantine/` 并计数，启动就绪；`/health/ready` 在监听后立即 200，核验在 20 秒内完成；编译窗口内被杀留下的 `helperPid=0` 或缺 `windowsSessionId` 的记录不拒绝下次启动；`npm run recover` 与启动核验结论一致并列出每条记录的文件名与原因。
- F17：取消语义矩阵。宽限期内 resolve 为 cancelled 且 `quiescent=true`：通道保留、`terminate()` 未被调用、下一轮热复用；reject 或晚于宽限期落定：通道销毁、`recovery=needs-native-resume`、下一轮重开且轨迹含 `context.lost`；`terminate()` 不能自证：仅该会话 blocked，新会话 204；`quiescent=false` 但 `terminate()` 自证：Run 按驱动返回的状态记录，不记 interrupted。
- E01：OpenCode 与 Pi 两种真实引擎使用同一 API，两种不同的南向接入实现通过共同契约；Hermes 可选，有证据则同样验证。
- E02：每个正式引擎证明模型/工具/资产配置有效；恢复和取消能力按通道验证。
- E03：能力包。启用列表变更不改代码；三个包各自投影到两个必过引擎并出现 `pack.projected` 原生事件；必需资产或探测失败在发送 Prompt 前失败；包内不含 `task_id`、固定答案与测试材料（静态检查）；每个包的自检步骤可在无引擎环境下执行。
- I01：内模工具调用完整往返，拒绝错误参数，不使用幻觉字段继续执行。
- I02：员工助手权限、登录与调用回执；未知提交结果不盲目重试。
- I03：官方已有材料上的真实任务、文件可打开、数据可对账、GUI任务结果不被清理撤销。

## 7. 基线准入

`npm run foundation:check` 必须通过依赖锁、目标 Node、类型检查、公共单测、HTTP 契约和边界检查。共同基线的 SHA、契约版本与锁哈希写入交接记录。源代码存在不等于已经通过该门禁。

Windows Job helper 的实机验证与完整依赖构建是单独证据项。未验证时必须如实记录，不能通过删除测试或加入 always-pass 分支获得准入。

## 8. 发布准入

`npm run release:check` 检查：共同基线通过、必过引擎（OpenCode、Pi）的真实 Pack 已实现、版本锁和内网验收证据、源码 commit 一致、Windows 身份和清理测试通过、无真实凭据、INSTRUCTION 可自动执行。两个必过引擎缺任一项即不可发布。

可选引擎（Hermes）有完整证据时计入发布矩阵并加分；无证据不阻断发布，只从矩阵中去掉，不得标为通过。

最终证据中禁止用 Mock、占位文件、仅声明 capability=true 或旧 commit 的结果代替真实验收。测试模型、回执和材料缺失时标记 not_run，不把它算作通过。
