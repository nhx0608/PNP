# 需求与交付范围

## 1. 依据与解释优先级

依据包括用户提供的《多 agent 引擎可替换架构实现—任务书》《调测指南》、两套网关接口规范、赛题 FAQ，以及明确的项目要求。原始接口材料位于 [参考目录](../reference/README.md)。官方要求与项目选择分别标注；不得把方案自行增加的约束表述成赛题强制条件。

## 2. 赛题约束

| ID | 原始要求 | PNP 实现决策 |
|---|---|---|
| R01 | Windows 10/11 运行，提交源码及编译启动方式 | 原生 Windows；不要求 WSL、Docker、数据库服务 |
| R02 | 至少两种不同 Agent 引擎 | OpenCode、Pi 为必过引擎，两者都通过正式验收才可发布；Hermes 为可选第三引擎，有证据加分，无证据不阻断发布 |
| R03 | 启动网关时能够指定并切换 Agent 引擎 | 环境变量 `AGENT_ENGINE` 与命令行参数 `--engine <engineId>` 等价，任选其一即可（`set AGENT_ENGINE=opencode && pnp.cmd start`，或 `gateway.cmd --engine opencode --port 6217`）；两者同时给出且不一致时以 `ENGINE_CONFIGURATION_CONFLICT` 启动失败，都不给出以 `ENGINE_NOT_FOUND` 失败。不同评测轮次停止后换另一个取值重新启动，不做运行时热切换 |
| R04 | 两套网关规范任选一套 | 完整实现通用 6217 规范；MyAgent 仅作为参考材料 |
| R05 | 主模型使用内部部署资源 | 每轮解析经过授权的内部模型配置，支持 API key、appid、自定义头及证书要求 |
| R06 | Rollout 完整执行记录；LLM-as-Judge 评价 | 消息、工具状态、停止原因和产物引用可追溯；不伪造执行成功 |
| R07 | 需要人工交互时必须提供自动提交接口 | 选择实现 Question/Permission 闭环；默认策略不覆盖组织权限拒绝 |
| R08 | 提交 `solution.zip`，包含 `INSTRUCTION.md` 和 `code/` | 发布脚本的 `--bundle` 模式产出可离线运行的交付包：源码之外含编译产物、生产依赖、固定版本 Node Windows 运行时与两个引擎，并写出各组件版本与 SHA-256；自检排除凭据、运行数据、数据库、日志与私钥 |
| R09 | 单个用例对所有参赛引擎分别执行并取最高分 | 评测路径每次只启动一个选定引擎，不在网关内双跑取优 |
| R10 | FAQ：可以提交安装包，但安装后仍必须提供本地网关接口并接受源码审查 | 安装包/一键启动器只是部署便利；评测事实源仍是赛题 Gateway HTTP API，源码始终完整交付 |
| R11 | FAQ：Agent/Harness 默认不会预装；不方便预置的环境依赖可由裁判手工安装 | 交付包自带 Node 运行时、依赖与两个 Harness，`pnp.cmd` 按"显式变量 → 包内 → 安装"顺序查找，全部命中时零网络；裁判也可自行安装后用 `PNP_*` 变量指定位置，或依赖就绪后直接 `gateway.cmd --engine ...`。公网下载只是最后一档回退，不是启动前提 |
| R12 | FAQ：评测系统按网关接口规范执行；评测文件会预置到沙箱 | 不增加评测私有入口；所有任务通过同一 Gateway API。测试文件只通过 Session `directory` 使用，不打包或硬编码数据集内容 |

评分权重：客观 70%；架构合理性 20%；创新性 5%；鲁棒性 5%。初赛截止后统一评测一次；FAQ 说明不会提供实时得分，开发阶段以 Agent 执行链路、真实结果和本地验收为准。

题目允许不实现跨引擎会话同步、持久化及多 Agent。PNP 的本地持久化是项目明确要求，不是赛题硬性条件。Question/Permission 在接口附件中有可选说明；当系统产生相应交互时，回传必须真实可用。

## 3. 项目约束

| ID | 项目要求 | 约束 |
|---|---|---|
| P01 | 自研稳定网关，连接可下载 Harness | 不能把仅切换模型或工具 CLI 计为接入不同引擎 |
| P02 | Session 本地持久化 | SQLite 保存会话、Run、消息和绑定；内存不能是唯一事实源 |
| P03 | 三人开发，A/B 同时开发 | 公共框架独立交付；A/B 不互相等待对方引擎代码 |
| P04 | C 对接内网 | 模型、工具、权限通过 IntegrationProvider 解耦；正式联合验证在内网 |
| P05 | 轻量并具备 DFX | 单网关、单执行槽加有界队列、本地存储、有限资源；不引入外部基础设施 |
| P06 | 可供没有会话上下文的 Agent 执行 | 文档、接口、任务、测试和分工在仓库内自足 |

## 4. 必须实现的能力

必须项包括：北向 API、持久化 Session/Run/Message、原生会话绑定、启动参数选择引擎、工作目录、模型绑定、SSE、取消与停止核验、错误归一化、有限超时、交互闭环、进程归属、能力包投影、内网工具和授权、自动部署说明、真实引擎与内网测试。

复杂但不可删除的项是：跨进程取消、崩溃后的资源核验、内部模型工具调用兼容、真实权限传递、消息终态与持久化一致性。这些直接影响评测正确性与外部副作用安全。

> 实现状态（2026-09-09，证据见 `../../verification/results.json`）：上列必须项中，"能力包投影"以 `settings.json` 驱动的 MCP/指令注入形式交付（Office MCP、Desktop MCP、指令文件），清单式能力包机制本身未实现；"内网工具和授权"与"内网测试"属 C 线，未交付、`not_run`。其余各项已实现并在 Windows 真机上以真实引擎冒烟验证。

## 5. 架构亮点及闭环

| 亮点 | 实施范围 | 必须提供的证据 |
|---|---|---|
| 一套 ACP Driver 支持多个 Harness | A 负责 OpenCode 的通道差异和配置；Hermes 可选 | 同一公共 Driver、不同 Pack 均通过契约测试（当前 ACP 上只有 OpenCode 一个已实现的 Pack；Hermes 是 `implementationProvided: false` 的扩展点示例，"多个 Harness"尚未在 ACP 通道上兑现） |
| 非 ACP 引擎接入 | B 负责 Pi RPC | 不修改 Gateway/Core 接入并完成真实任务 |
| 通道级能力描述 | 引擎版本 × 通道 × 模型 × 资产配置 | 区分声明、探测、实测，不用全为 true 的能力矩阵 |
| 原生能力保留 | 技能/工具注入以及至少一种可验证的原生扩展 | 配置输入、引擎确认、执行轨迹和结果验证 |
| 引擎无关的能力包 | 三个能力包由配置启用，投影到每个必过引擎 | 同一包在两个引擎上都有投影事件与任务产物（**未按此形式实现**：当前由 `settings.json` 的 MCP/指令注入承担，同一配置在两个引擎的冒烟中各自完成 MCP 往返；清单、探测与 `pack.projected` 未实现） |
| 可恢复会话与诚实终态 | 本地状态 + 原生恢复 + 停止证据 | 重启后历史不丢；未核验停止只阻断该会话；不重放任务 |
| 共用开发契约 | A/B/C 同一框架和验收套件 | 独立开发分支可组合运行，公共接口无私有分叉 |

不以堆叠模块数量、编写泛化平台或增加未经测试的引擎数量作为亮点。

## 6. V2 范围

跨引擎无损会话迁移、运行中热切换、外层 Dynamic Workflow/Agent Team/Room、自动引擎路由、统一自进化、跨引擎记忆同步、分布式多副本、HTTP/SDK 通道的完整独立实现属于 V2。V1 允许引擎在自己的执行器内部使用这些原生能力，但不承诺已经实现对应的网关编排语义。

## 7. 已知评测覆盖

10 个参数样例涉及 Word 精确改写、CSV 客户分析、库存分析、PPT 编辑/生成、即时通讯、递归文件删除、DOCX 表格转 XLSX、最新资讯检索。它们验证通用系统和 Harness 的能力，不是网关分支条件。不得使用 `task_id/category/difficulty` 硬编码答案、工具选择或产物。

FAQ 已确认：评测数据中的文件类输入会预先部署到沙箱环境，因此系统只需正确接收并隔离 `directory`，不得把已知样例文件复制进提交包，也不得基于固定文件名走旁路逻辑。

能力注入是一等交付物。三个能力包 `office`、`windows-desktop`、`web-search` 各有所有者、目录与验收项，定义见[契约第 10 节](contracts.md#10-能力包)；它们覆盖已知样例的九条，与引擎接入同等优先。实现状态（2026-09-09）：三个包的清单机制未实现；`office` 的能力由 Office MCP 服务器（`code/src/tools/office-mcp`）提供，`windows-desktop` 只交付了 Desktop MCP 的列举/打开固定应用子集，`web-search` 只有 Office MCP 的 `web_fetch`（GET → 文本，无检索）。

工具来源优先级：已有 Harness 能力、已授权员工助手 CLI、能力包内的 MCP/Skills、确实缺失的最小补充。Python、Office 组件与视觉模型属于各能力包的运行时依赖，由探测规则在打开通道时判定；不把它们变成 Gateway 本身的无条件依赖。
