# 已知评测用例基线

> 更新时间：2026-09-04  
> 本文只整理目前已知的评测参数及其代表的能力覆盖面。当前仓库为公开仓库，因此不写入内部账号、工号、appid、Token、内部地址等不宜公开的信息。

## 1. 说明

当前已获得 10 条评测任务参数。它们用于验证不同 Agent Harness 在 Windows 办公环境中的实际任务完成能力。

这些任务**不是系统架构本身的功能列表**。本项目的核心仍然是：

- 自研统一 Agent 网关；
- 接入多个真实 Harness；
- 让不同 Harness 通过同一评测协议执行相同任务；
- 保持业务层和网关核心不依赖具体引擎。

## 3. 详细任务描述

### 3.1 `office_011` — 文档润色改写

目标：

- 打开测试目录中的 OpenClaw 学术洞察报告 DOCX；
- 对“执行摘要”中涉及 OpenClaw 影响力和行业采用情况的两段文字进行润色；
- 风格要求更克制、正式、适合内部研究汇报；
- 不改变事实信息和章节结构；
- 保留 GitHub Stars、MIT、自托管、主流云厂商采用等关键信息；
- 另存为新 DOCX。

代表能力：

- Word 文档读取和精确编辑；
- 保格式改写；
- 文件另存；
- 文本语义理解与事实保持。

### 3.2 `office_014` — 违约风险分析

目标：

- 基于 `task.csv`；
- 分析 `credit_score`、`debt_ratio`、`late_payments`、`loan_amount` 与 `defaulted` 的关系；
- 输出中文 Markdown；
- 至少包含高风险特征、低风险特征、3 条可执行建议；
- 提供按风险高低排序的样本观察表。

代表能力：

- CSV 读取；
- 数据探索和统计分析；
- 风险分层；
- 报告生成。

### 3.3 `office_015` — 客户分层与违约特征分析

目标：

- 基于同一份 `task.csv`；
- 从 `age`、`income`、`monthly_spend`、`debt_ratio` 四个字段进行客户分层；
- 判断哪些组合更容易出现 `defaulted=1`；
- 不能只给均值；
- 需要补充分层口径、异常样本和业务含义；
- 输出 500–800 字中文分析短报。

代表能力：

- 多字段分层分析；
- 组合特征分析；
- 异常样本识别；
- 长度和内容约束下的报告生成。

### 3.4 `office_018` — 库存补货优先级分析

目标：

- 基于 Excel 中的“库存管理台账”；
- 重点关注当前库存、安全库存、最大库存、采购周期和供应商；
- 输出中文备忘录；
- 分成“高优先级补货”“需要观察”“库存相对安全”三类；
- 给出排序依据和建议动作。

代表能力：

- Excel 读取；
- 表格字段理解；
- 规则/指标分析；
- 分层输出。

### 3.5 `office_022` — PPT 主体结构优化

目标：

- 编辑既有 PPT 第 3–7 页；
- 对“行业概览—用户规模—用户特征—内容生态—推荐机制”进行更连贯的讲述组织；
- 保留已有数据点；
- 减少碎片化短句；
- 每页形成“结论 + 证据”版式；
- 另存为新 PPTX。

代表能力：

- PPT 内容理解；
- 指定页编辑；
- 结构重组；
- 视觉版式优化；
- 保留原始数据点。

### 3.6 `office_028` — 即时通讯消息发送

目标：

- 向指定企业即时通讯联系人发送一条固定测试消息。

公开仓库不记录真实工号或账号。

代表能力：

- Windows 桌面应用操作；
- 联系人搜索；
- 消息发送；
- 外部副作用控制；
- 重试/幂等风险处理。

### 3.7 `office_035` — 生成 OpenClaw 介绍 PPT

目标：

- 生成不超过 5 页的 OpenClaw 介绍 PPT；
- 包含基本介绍、核心功能、核心架构、部署方式、部署依赖；
- 不需要用户确认 PPT 大纲；
- 保存为测试目录下指定 PPTX。

代表能力：

- 信息组织；
- 文档/PPT 生成；
- 版式和页数约束；
- 文件落盘。

### 3.8 `office_103` — 删除匹配文件

目标：

- 递归扫描测试目录及其子目录；
- 删除所有**文件名**中包含指定中文地名关键字的文件。

公开文档不保留具体敏感业务目录之外的信息。

代表能力：

- Windows 文件系统；
- 递归搜索；
- 文件删除；
- 精确作用域控制。

### 3.9 `office_132` — DOCX 表格导出 Excel

目标：

- 分析指定 DOCX；
- 提取其中所有表格；
- 导出为 Excel；
- 如果有多个表格，分别放在不同 Sheet；
- 输出到另一个备份目录中的指定 XLSX。

代表能力：

- DOCX 表格解析；
- 多表格识别；
- XLSX 生成；
- 多 Sheet 写入；
- 跨目录文件输出。

### 3.10 `office_139` — 最新资讯收集与分析

目标：

- 收集并分析自动驾驶领域的最新资讯和动态。

代表能力：

- 实时网页检索；
- 信息筛选；
- 来源整合；
- 时效性判断；
- 调研和综述。

## 5. 对 Harness 的直接要求

从这些样例可以观察到，效果较好的参赛 Harness 至少需要具备或能够通过 Tool / MCP / Skill 获得：

- 本地文件系统访问；
- Windows 命令/进程执行；
- Office 文件处理能力；
- Python / Node 等代码执行能力；
- 网页搜索或浏览能力；
- 必要时的 Windows Computer Use；
- 多步 Agent Loop；
- 工具调用结果继续进入后续推理；
- 任务结束前能够检查产物或环境状态。

这些能力可以由 Harness 原生提供，也可以由 PNP 通过统一资产层注入；核心原则是不把具体任务执行逻辑硬编码进网关。

## 6. 不应针对样例硬编码

实现中不应该依赖：

- `task_id == office_xxx`；
- 固定测试文件内容；
- 固定文件名判断后直接执行预设答案；
- 固定联系人账号；
- 任何未知隐藏数据集的猜测。

网关负责连接和治理 Harness，具体任务仍应由 Agent 根据用户 Prompt、工作目录和工具环境自主完成。
